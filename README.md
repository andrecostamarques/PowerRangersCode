## Dependencies Instalation
As Cuda and Torch cannot be installed via the enviroment.yml. The following code should be used.

```bash
conda env create -n PowerRanger-env python=3.12
conda activate PowerRanger-env
pip3 install torch torchvision --index-url https://download.pytorch.org/whl/cu130
conda env update --file environment.yml --prune
```

## Overview
PowerRangersCode is a project enabling Neural Network Training with Learnable Selection Masks. It implements a custom module using the Straight-Through Estimator (STE) to learn hard binary masks for feature selection or pruning.

## Repository Structure

- **`src/`**: Contains the source code for the project, including models, training scripts, and utilities.
- **`notebooks/`**: Contains Jupyter notebooks for running experiments and analyzing results.
- **`data/`**: Directory for storing datasets.

## Checkpoints
All model checkpoints (.pth) will be stored on a soft-link `checkpoints`. You may choose where this link points to.

## Technical Overview

The project follows a modular pipeline orchestrated by the `training_loop.py` script. The architecture separates configuration, data management, and training logic to ensure flexibility and reproducibility.

### 1. Entry Point: `training_loop.py`
The execution begins here. This script is responsible for:
*   **Data Retrieval**: Uses `DatasetsDict` to fetch standard datasets (e.g., MNIST) with predefined transformations.
*   **Hyperparameter Definition**: Defines a raw dictionary containing all experiment settings (learning rates, batch sizes, model types, lambda parameters).
*   **Configuration Object**: Instantiates `TrainingConfig` to validate and structure these settings.
*   **Trainer Initialization**: Passes the config to `StaticMaskTraining` and triggers the `.train()` method.

### 2. Configuration & Data: `TrainingConfig`
Acts as the blueprint for the experiment.
*   Stores all hyperparameters and class references (e.g., which optimizer or loss function to use).
*   **Data Preparation**: The `get_dataloader()` method handles the splitting of training data into training/validation sets and creates PyTorch DataLoaders using the specified batch size and seed.

### 3. Training Orchestrator: `StaticMaskTraining`
This class encapsulates the entire training lifecycle. Upon initialization, it:
*   **Instantiates Models**: Creates the classification model (e.g., `LeNet5`) and the `SelectionMask` on the target device (CPU/GPU).
*   **Sets up Optimization**: Initializes the optimizer (e.g., AdamW) for both model and mask parameters.
*   **Prepares Loss Logic**: Initializes `TotalLoss` and `LambdaScheduler`.

#### Training Loop (`train` method)
For each epoch, the orchestrator:
1.  **Training Step (`train_epoch`)**:
    *   Applies the mask: `X_masked = mask_model(X)`.
    *   Predicts: `y_pred = model(X_masked)`.
    *   Calculates Loss: Uses `TotalLoss` to compute `Model Loss + (Lambda * Mask Loss)`.
    *   Updates weights via backpropagation.
2.  **Validation Step (`validate_epoch`)**:
    *   Evaluates the model on unseen validation data to compute accuracy and confusion matrices.
3.  **Lambda Scheduling**:
    *   Calls `LambdaScheduler.adapt_lambda()` to adjust the sparsity penalty weight based on the total loss trend.
4.  **Logging & Checkpointing**:
    *   Saves metrics to CSV and serializes the model state to `.pth` files in the `checkpoints/` directory.

### 4. Evaluation & Analysis
Once training is complete, the pipeline shifts to evaluation using the `ModelTester` class and Jupyter Notebooks.

*   **ModelTester**: This utility is responsible for loading specific checkpoints (restoring both model and mask states) and running inference on the test dataset. It computes final metrics such as the confusion matrix to provide a detailed breakdown of model performance.
*   **Jupyter Notebooks**: Located in the `notebooks/` directory, these provide an interactive environment for visualizing results. They are used to plot loss curves, analyze the evolution of the lambda parameter, visualize the learned binary masks as heatmaps, and interpret the confusion matrices generated by the tester.
